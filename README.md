# Go с нуля до собеседования 🐹

Мой личный путь изучения языка Go: теория, практические задачи, поиск ошибок, разбор кода, Git/GitHub и подготовка к собеседованию.

Цель проекта — не просто запомнить синтаксис Go, а научиться **самостоятельно писать, читать и отлаживать код**, понимать причины ошибок и постепенно перейти от учебных задач к реальным backend-проектам.

# 📚 Как проходит обучение

Каждая тема проходит несколько этапов:

1. 🧠 Теория.
2. 🎯 Самостоятельная практическая задача.
3. 🔎 Разбор решения и ошибок.
4. 🐛 Поиск ошибок в чужом коде.
5. 📝 Фиксация важных моментов в конспекте.
6. 🐙 Отдельный Git-коммит для законченного изменения.
7. ☁️ Push результата на GitHub.

Каждые **5 новых уроков** завершаются большой контрольной работой.

Контрольная включает:

```text
теория
↓
чтение кода
↓
поиск и исправление багов
↓
самостоятельное написание программы
↓
struct / методы / error
↓
Git
```

После контрольной выполняется отдельная **работа над ошибками**, после чего начинается следующий пятииурочный блок.

Главный принцип:

> **Сначала пытаюсь решить самостоятельно. Готовое решение использую только после разбора собственных ошибок.**

# 🐛 Bug Hunt & Code Review

Отдельный формат практики:

> **Сначала определить, действительно ли код содержит ошибку. Только после этого искать исправление.**

В заданиях встречались ошибки:

```text
неправильный порядок вычислений
неправильный receiver
отсутствующий return
бесконечный цикл
неправильная работа со счётчиком
ошибочное накопление суммы
изменение состояния до валидации
использование старого результата
```

Также были задания, где код был полностью корректен.

Цель:

> **Не искать ошибку любой ценой, а понимать поведение программы.**

# 🐙 Git и GitHub

Git используется не только для хранения проекта, но и как часть процесса обучения.

Главный принцип:

> **Одно законченное логическое изменение → один отдельный коммит.**

Примеры:

```text
feat: add calculator
feat: add student struct
feat: add student methods
feat: add bank account
feat: add user profile
feat: practice arrays
docs: update go notes
chore: update gitignore
```

Не использовать один огромный коммит для нескольких независимых изменений.

---

## Рабочий Git-процесс

После завершения отдельной задачи:

```powershell
git status
git add .\practice\XX-task\main.go
git diff --cached
git commit -m "feat: add ..."
git push origin main
git status
```

Важно добавлять в staging только те файлы, которые относятся к текущему изменению.

# 🎯 Главный принцип обучения

Цель — не просто получить работающий код.

Важно понимать:

```text
почему код работает
↓
что происходит во время выполнения
↓
где возникает ошибка
↓
почему она возникает
↓
как найти её самостоятельно
↓
как исправить
↓
как сделать код понятнее
```

Каждая ошибка — часть обучения.

Каждый практический проект — часть портфолио.

Каждый Git-коммит — часть истории развития проекта.

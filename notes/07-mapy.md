# Конспект 7. Мапы (maps)

## 1. Объявление и базовые операции

Мапа — встроенная в язык хеш-таблица: ключ → значение.

```go
var m map[string]int          // nil-мапа! Читать можно, писать — PANIC
m2 := make(map[string]int)     // пустая, готовая к записи мапа
m3 := map[string]int{          // литерал мапы
    "a": 1,
    "b": 2,
}

m2["x"] = 10        // запись
value := m2["x"]     // чтение, 10
missing := m2["y"]   // чтение несуществующего ключа — ВЕРНЁТ ZERO VALUE типа, а не ошибку! 0
```

**Критически важное отличие от слайсов:** запись в nil-мапу вызывает панику, а чтение — нет:

```go
var m map[string]int
fmt.Println(m["key"]) // 0, всё ок, паники нет
m["key"] = 1           // PANIC: assignment to entry in nil map
```

## 2. Проверка существования ключа (comma, ok idiom)

Так как чтение отсутствующего ключа тихо возвращает нулевое значение, нужен способ отличить "ключа нет" от "ключ есть, а значение реально равно нулю":

```go
m := map[string]int{"a": 0}

value, ok := m["a"]
fmt.Println(value, ok) // 0 true  — ключ есть, значение действительно 0

value2, ok2 := m["b"]
fmt.Println(value2, ok2) // 0 false — ключа нет вообще
```

Эта идиома `value, ok := ...` используется не только с мапами — она же применяется при чтении из канала и при type assertion (см. конспекты 9 и 12).

## 3. Удаление ключа и итерация

```go
delete(m, "a") // безопасно вызывать, даже если ключа нет — ничего не произойдёт

for key, value := range m {
    fmt.Println(key, value)
}
```

**Важная деталь для собеседования:** порядок итерации по мапе в Go **намеренно рандомизирован** на каждом запуске программы. Это сделано специально, чтобы разработчики не полагались на несуществующий "порядок" мапы. Если порядок важен — нужно отдельно собрать и отсортировать ключи:

```go
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
sort.Strings(keys)

for _, k := range keys {
    fmt.Println(k, m[k])
}
```

## 4. Мапа как множество (set)

В Go нет встроенного типа Set — его эмулируют мапой с типом значения `struct{}` (нулевого размера, не тратит память):

```go
set := map[string]struct{}{
    "apple":  {},
    "banana": {},
}

_, exists := set["apple"]
fmt.Println(exists) // true

set["cherry"] = struct{}{} // добавление
delete(set, "banana")       // удаление
```

Альтернатива попроще для читаемости (но с небольшим перерасходом памяти) — `map[string]bool`.

## 5. Какие типы можно использовать как ключ мапы

Ключом мапы может быть любой **сравнимый** (comparable) тип: числа, строки, bool, указатели, массивы (фиксированного размера!), структуры, у которых все поля сравнимы.

**Нельзя** использовать как ключ: слайсы, мапы, функции — потому что они несравнимы (нет корректно определённого `==` между двумя слайсами).

```go
type Point struct {
    X, Y int
}

visited := make(map[Point]bool)
visited[Point{1, 2}] = true
fmt.Println(visited[Point{1, 2}]) // true — структуры сравниваются "по значению" полей
```

## 6. Мапа и конкурентный доступ — забегая вперёд к конспекту 12-13

**Мапы в Go не потокобезопасны.** Одновременное чтение и запись из разных горутин без синхронизации — гонка данных (data race), которая может привести к панике программы в runtime:

```go
// ОПАСНО без синхронизации:
var m = make(map[string]int)
go func() { m["a"] = 1 }()
go func() { m["b"] = 2 }() // fatal error: concurrent map writes
```

Правильные решения — обернуть доступ в `sync.Mutex` (конспект 13) или использовать `sync.Map` из стандартной библиотеки для специфичных сценариев (например, кэш с редкой записью и частым чтением).

## 7. Мапа как аргумент функции

Как и слайсы, мапа — reference type: передаётся "по ссылке" в том смысле, что копируется только заголовок, а не сами данные, поэтому изменения содержимого внутри функции видны и снаружи:

```go
func addEntry(m map[string]int) {
    m["new"] = 1 // изменение видно и в вызывающем коде — в отличие от append у слайсов!
}

data := make(map[string]int)
addEntry(data)
fmt.Println(data) // map[new:1]
```

# Конспект 5. Указатели (pointers)

## 1. Зачем указатели, если это не C

По умолчанию в Go **все значения передаются по копии** — и в переменные, и в аргументы функций. Указатель — способ передать не копию значения, а адрес в памяти, где оно лежит, чтобы можно было это значение изменить "по месту".

```go
x := 10
p := &x        // p — указатель на x, содержит АДРЕС переменной x
fmt.Println(p)  // выведет что-то вроде 0xc0000140a0
fmt.Println(*p) // разыменование (dereference) — получить значение по адресу: 10

*p = 20         // изменяем значение x ЧЕРЕЗ указатель
fmt.Println(x)  // 20 — исходная переменная изменилась!
```

- `&x` — оператор "взять адрес" (address-of).
- `*p` — оператор "разыменовать" (dereference) — то есть получить значение, на которое указывает указатель. Обрати внимание: символ `*` используется и для объявления типа указателя, и для разыменования — это разные роли одного символа в зависимости от контекста.
- `var p *int` — объявление переменной типа "указатель на int". Нулевое значение указателя — `nil`.

## 2. Передача по значению vs передача по указателю

```go
func increment(x int) {
    x++ // меняет только локальную КОПИЮ
}

func incrementPtr(x *int) {
    *x++ // меняет значение по адресу — то есть оригинал
}

func main() {
    n := 5
    increment(n)
    fmt.Println(n) // 5 — не изменилось

    incrementPtr(&n)
    fmt.Println(n) // 6 — изменилось
}
```

**Когда использовать указатели в функциях:**
1. Когда функция должна изменить переданное значение (как выше).
2. Когда копирование большой структуры дорого по памяти/CPU — передать указатель дешевле, чем копировать всю структуру.
3. Когда нужно явно показать, что значение может отсутствовать — `nil` для указателя означает "значения нет" (у обычного `int` нет "пустого" состояния, у `*int` — есть).

## 3. Указатели на структуры

```go
type User struct {
    Name string
    Age  int
}

func birthday(u *User) {
    u.Age++ // Go сам разыменовывает указатель для доступа к полю —
            // не нужно писать (*u).Age, хотя так тоже можно
}

user := User{Name: "Alex", Age: 25}
birthday(&user)
fmt.Println(user.Age) // 26
```

Функция `new()` — встроенный способ создать указатель на нулевое значение типа:

```go
p := new(int)     // p — *int, указывает на 0
u := new(User)    // u — *User, указывает на User{Name: "", Age: 0}
```

На практике для структур гораздо чаще используют конструктор вида `&User{...}`, а не `new`:

```go
user := &User{Name: "Alex", Age: 25} // user имеет тип *User
```

## 4. Указатели и слайсы/мапы — важный нюанс

Слайсы, мапы, каналы в Go — это уже так называемые **reference types** (внутри себя они содержат указатель на данные), поэтому передавать их по указателю для *изменения содержимого* обычно не требуется:

```go
func addItem(items []int, item int) {
    items = append(items, item) // может не сработать, если превышена capacity — см. конспект 6!
}

func modifyFirst(items []int) {
    if len(items) > 0 {
        items[0] = 100 // а вот ЭТО сработает всегда — меняем элемент по индексу
                        // в общем базовом массиве, на который ссылается слайс
    }
}
```

Подробно про то, почему `append` внутри функции не всегда меняет исходный слайс — в конспекте 6 (слайсы).

## 5. nil-указатель и паника при разыменовании

```go
var p *int
fmt.Println(*p) // PANIC: runtime error: invalid memory address or nil pointer dereference
```

Обращение к полю через nil-указатель на структуру — тоже частая причина паники в реальных проектах:

```go
var u *User
fmt.Println(u.Name) // PANIC, если структура не была создана
```

**Правило безопасности:** перед разыменованием указателя, полученного откуда-то извне (из функции, из мапы, из JSON), всегда проверяй `if p != nil`.

## 6. Указатели vs значения в методах (забегая вперёд к конспекту 8)

```go
type Counter struct {
    count int
}

// Receiver по значению — метод работает с КОПИЕЙ Counter, изменения не сохранятся
func (c Counter) IncrementByValue() {
    c.count++
}

// Receiver по указателю — метод работает с оригиналом
func (c *Counter) IncrementByPointer() {
    c.count++
}

c := Counter{}
c.IncrementByValue()
fmt.Println(c.count) // 0 — не изменилось

c.IncrementByPointer()
fmt.Println(c.count) // 1 — изменилось (Go сам берёт &c при вызове)
```

Практическое правило: если хотя бы одному методу типа нужен receiver-указатель (для изменения состояния), обычно **все** методы этого типа делают receiver-указателями — для консистентности API.

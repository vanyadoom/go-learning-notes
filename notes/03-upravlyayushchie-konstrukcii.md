# Конспект 3. Управляющие конструкции

## 1. if / else

```go
age := 20

if age >= 18 {
    fmt.Println("совершеннолетний")
} else if age >= 14 {
    fmt.Println("подросток")
} else {
    fmt.Println("ребёнок")
}
```

Особенности синтаксиса Go (частые ошибки новичков):
- Скобки `()` вокруг условия **не нужны и не приняты**.
- Фигурные скобки `{}` **обязательны**, даже для одной строки.
- Открывающая скобка `{` обязана стоять на той же строке, что и `if` (иначе компилятор автоматически вставит `;` и сломает код — это следствие правил автоматической вставки точки с запятой в Go).

### if с коротким объявлением переменной

Очень частая идиома в Go — особенно вместе с обработкой ошибок:

```go
if err := doSomething(); err != nil {
    fmt.Println("ошибка:", err)
    return
}
// переменная err видна только внутри блока if/else
```

Переменная, объявленная в `if`, живёт в области видимости самого `if` и всех его `else`, но не снаружи. Это позволяет не засорять внешнюю область видимости временными переменными вроде `err`.

## 2. switch

В Go `switch` гораздо мощнее, чем в C/Java — и `break` после `case` не нужен, он подразумевается по умолчанию (обратное поведение по сравнению с C!).

```go
day := 3

switch day {
case 1, 7:
    fmt.Println("выходной")
case 2, 3, 4, 5, 6:
    fmt.Println("рабочий день")
default:
    fmt.Println("некорректный день")
}
```

### switch без выражения (замена длинной цепочке if-else)

```go
score := 85

switch {
case score >= 90:
    fmt.Println("A")
case score >= 75:
    fmt.Println("B")
case score >= 60:
    fmt.Println("C")
default:
    fmt.Println("F")
}
```

### fallthrough — принудительный переход к следующему case

```go
switch 2 {
case 1:
    fmt.Println("один")
case 2:
    fmt.Println("два")
    fallthrough
case 3:
    fmt.Println("три") // выполнится тоже, из-за fallthrough
case 4:
    fmt.Println("четыре") // не выполнится
}
// Вывод: два / три
```

### type switch (пригодится в интерфейсах, конспект 9)

```go
func describe(i interface{}) {
    switch v := i.(type) {
    case int:
        fmt.Println("это int:", v)
    case string:
        fmt.Println("это строка:", v)
    default:
        fmt.Printf("неизвестный тип: %T\n", v)
    }
}
```

## 3. for — единственный цикл в Go

В Go нет `while` и `do-while` — всё выражается через `for` в разных формах.

```go
// Классический for с тремя частями (как в C)
for i := 0; i < 5; i++ {
    fmt.Println(i)
}

// Аналог while — только условие
n := 0
for n < 5 {
    n++
}

// Бесконечный цикл
for {
    fmt.Println("вечно")
    break // без break/return будет крутиться бесконечно
}

// Цикл по коллекции (range)
nums := []int{10, 20, 30}
for index, value := range nums {
    fmt.Println(index, value)
}

// Если индекс не нужен — используем _
for _, value := range nums {
    fmt.Println(value)
}

// Если нужен только индекс
for index := range nums {
    fmt.Println(index)
}
```

### break и continue с метками (labels)

Пригождается при вложенных циклах, когда `break` внутри вложенного цикла должен прервать не только его, а внешний:

```go
outer:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            continue outer // переходит к следующей итерации ВНЕШНЕГО цикла
        }
        if i == 2 {
            break outer // прерывает ВНЕШНИЙ цикл целиком
        }
        fmt.Println(i, j)
    }
}
```

## 4. Особенность: значение переменной цикла (частая ловушка, до Go 1.22)

**Важно для собеседования** — до версии Go 1.22 переменная цикла `range` была **одна и та же** на всех итерациях (переиспользовалась), что приводило к классической ошибке при захвате переменной в горутинах/замыканиях:

```go
// ДО Go 1.22 — БАГ:
funcs := []func(){}
for _, v := range []int{1, 2, 3} {
    funcs = append(funcs, func() {
        fmt.Println(v) // все три функции напечатают "3" — последнее значение v!
    })
}

// Исправление в старых версиях — создать локальную копию:
for _, v := range []int{1, 2, 3} {
    v := v // теневая переменная — новая копия на каждой итерации
    funcs = append(funcs, func() { fmt.Println(v) })
}
```

**С Go 1.22+ этот баг исправлен на уровне языка** — каждая итерация `for` создаёт новую переменную автоматически, старый код с `v := v` работает по-прежнему, но уже не обязателен. На собеседовании эту деталь часто спрашивают именно как «что изменилось в Go 1.22».

### Задача 1: перевернуть строку с учётом Unicode

Условие: написать функцию `ReverseString(s string) string`, которая корректно разворачивает строку, включая кириллицу и эмодзи (наивный разворот по байтам сломает многобайтовые символы).

```go
func ReverseString(s string) string {
    runes := []rune(s) // конвертация в []rune — ключевой момент
    for i, j := 0, len(runes)-1; i < j; i, j = i+1, j-1 {
        runes[i], runes[j] = runes[j], runes[i]
    }
    return string(runes)
}
```

### Задача 2: FizzBuzz

Условие: числа от 1 до 100; кратные 3 — "Fizz", кратные 5 — "Buzz", кратные обоим — "FizzBuzz", иначе — само число.

```go
func FizzBuzz(n int) []string {
    result := make([]string, 0, n)
    for i := 1; i <= n; i++ {
        switch {
        case i%15 == 0:
            result = append(result, "FizzBuzz")
        case i%3 == 0:
            result = append(result, "Fizz")
        case i%5 == 0:
            result = append(result, "Buzz")
        default:
            result = append(result, strconv.Itoa(i))
        }
    }
    return result
}
```

## 4. Формат живого собеседования — практический совет

На большинстве Go-собеседований (особенно live-coding) важнее не "знать наизусть всё", а:
1. **Проговаривать ход мыслей вслух** — интервьюер оценивает процесс, а не только финальный код.
2. **Явно проверять ошибки** в коде на собеседовании — даже в псевдокоде, это показывает привычку.
3. **Уметь объяснить сложность (Big O)** своего решения, а не только написать его.
4. **Не бояться сказать "не знаю, но предполагаю..."** вместо угадывания наугад — это ценится больше, чем уверенный неправильный ответ.

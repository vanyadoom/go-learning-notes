# Конспект 1. Введение в Go

## 1. Что такое Go и зачем он нужен

Go (Golang) — язык программирования, созданный в Google (2009 г.) авторами: Роб Пайк, Кен Томпсон, Роберт Гризмер. Создавался как реакция на проблемы больших C++ проектов: медленная компиляция, сложность, неявные зависимости.

**Философия языка (важно понимать, а не только знать синтаксис):**

- **Простота важнее выразительности.** В Go нет: классов, наследования, исключений (try/catch), generics до версии 1.18, перегрузки функций, тернарного оператора. Это осознанное решение — меньше способов сделать одно и то же.
- **Явное лучше неявного.** Ошибки возвращаются явно (`err != nil`), а не «вылетают» через исключения. Приведение типов всегда явное.
- **Композиция вместо наследования.** Вместо иерархий классов — встраивание структур и интерфейсы.
- **Конкурентность как часть языка**, а не библиотека поверх него (горутины, каналы — ключевые слова языка).
- **Скорость компиляции.** Go компилируется в нативный машинный код за секунды даже на больших проектах.
- **Один бинарник.** Go компилирует программу в один исполняемый файл без внешних зависимостей (в отличие от Python/Node, где нужен интерпретатор).

**Где используется:** backend-сервисы (Kubernetes, Docker написаны на Go), микросервисы, CLI-утилиты, сетевые серверы, инфраструктурный софт. Это основная причина, почему Go так востребован в вакансиях backend/DevOps.

## 2. Установка и инструменты

Скачивается с https://go.dev/dl/. После установки проверяется командой:

```bash
go version
```

Основные команды, которые будешь использовать каждый день:

```bash
go run main.go      # скомпилировать и сразу запустить (без сохранения бинарника)
go build            # скомпилировать в исполняемый файл в текущей папке
go build -o app     # скомпилировать с указанным именем файла
go fmt ./...        # автоматически отформатировать весь код в проекте
go vet ./...        # статический анализ, находит подозрительные конструкции
go mod init имя     # создать новый модуль (проект)
go mod tidy         # скачать недостающие зависимости и удалить лишние из go.mod
go test ./...       # запустить все тесты в проекте
go doc fmt.Println  # посмотреть документацию по функции/пакету прямо в терминале
```

> **Важная деталь для собеседования:** `go run` — это фактически `go build` во временную папку + запуск. В продакшене всегда используют `go build`, чтобы получить бинарник и деплоить именно его.

## 3. Структура проекта и модули

С 2019 года (Go 1.11+) стандартный способ управления зависимостями — **Go Modules** (раньше был GOPATH, про него могут спросить на собеседовании как про legacy-подход, но использовать его не нужно).

Создание нового проекта:

```bash
mkdir myproject && cd myproject
go mod init github.com/username/myproject
```

Это создаёт файл `go.mod`:

```go
module github.com/username/myproject

go 1.21

require (
    github.com/some/dependency v1.2.3
)
```

**Разбор построчно:**
- `module ...` — уникальное имя модуля. По конвенции — это путь, по которому модуль можно импортировать (обычно совпадает с адресом репозитория на GitHub), но физически по сети никуда не ходит, если ты не публикуешь свой код.
- `go 1.21` — минимальная версия Go, необходимая для сборки.
- `require (...)` — список внешних зависимостей с точными версиями. Добавляется автоматически, когда ты импортируешь пакет и запускаешь `go mod tidy`.

Рядом появляется файл `go.sum` — хранит криптографические хэши зависимостей для защиты от подмены пакетов (аналог `package-lock.json` в Node.js). Его не редактируют руками, но обязательно коммитят в git.

**Типичная структура более-менее реального проекта:**

```
myproject/
├── go.mod
├── go.sum
├── main.go              # точка входа
├── internal/            # код, доступный только внутри этого модуля
│   └── service/
│       └── service.go
├── pkg/                 # код, который можно импортировать из других модулей
│   └── utils/
│       └── utils.go
└── cmd/                 # если бинарников несколько
    └── server/
        └── main.go
```

`internal/` — специальное имя папки, которое **компилятор** (а не просто конвенция) запрещает импортировать извне модуля. Это встроенный языковой механизм инкапсуляции на уровне проекта.

## 4. Первая программа — разбор по косточкам

```go
package main

import "fmt"

func main() {
    fmt.Println("Привет, Go!")
}
```

- `package main` — объявление пакета. Каждый `.go`-файл принадлежит какому-то пакету. Пакет `main` — особенный: это признак того, что из данного пакета собирается исполняемый файл (а не библиотека).
- `import "fmt"` — подключение пакета стандартной библиотеки `fmt` (форматированный ввод-вывод, аналог printf в C).
- `func main()` — тоже особенная функция: именно с неё стартует выполнение программы. В пакете `main` она обязана существовать, и она не принимает аргументов и не возвращает значений.
- `fmt.Println(...)` — вызов функции `Println` из пакета `fmt`. Точка — обращение к экспортируемому имени пакета.

**Правило экспорта имён (критически важно и не имеет аналогов в большинстве языков):** в Go нет ключевых слов `public`/`private`. Видимость определяется **регистром первой буквы**:

```go
func PublicFunction() {}   // с большой буквы — доступна из других пакетов (экспортируется)
func privateFunction() {}  // с маленькой буквы — доступна только внутри своего пакета
```

Это же правило действует для переменных, констант, структур, полей структур, методов — вообще для всех идентификаторов верхнего уровня.

## 5. Комментарии

```go
// однострочный комментарий

/*
   многострочный
   комментарий
*/

// PublicFunction делает что-то полезное.
// Комментарий прямо перед объявлением с большой буквы, начинающийся
// с имени функции — это конвенция для документации (go doc её подхватывает).
func PublicFunction() {}
```

## 6. Компиляция под другую платформу (кросс-компиляция)

Ещё одна вещь, которую любят спрашивать на собеседованиях как отличие от Python/Java — Go умеет собирать бинарник под любую ОС/архитектуру без установки эмуляторов:

```bash
GOOS=linux GOARCH=amd64 go build -o app-linux
GOOS=windows GOARCH=amd64 go build -o app.exe
GOOS=darwin GOARCH=arm64 go build -o app-mac
```

`GOOS` — целевая операционная система, `GOARCH` — архитектура процессора. Это работает благодаря тому, что Go компилируется напрямую в машинный код без промежуточной виртуальной машины.

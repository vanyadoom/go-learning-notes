# Тема 31: Углубленная работа с ошибками (Error Handling)

В Go ошибки — это значения, а не исключения. Это фундаментальное отличие от многих других языков.

## 1. Интерфейс `error`
В основе всего лежит простой интерфейс:
```go
type error interface {
    Error() string
}

Любой тип, у которого есть метод Error() string, является ошибкой. Стандартная библиотека предоставляет функцию для создания простых ошибок:

import "errors"
err := errors.New("описание проблемы")

2. Возврат ошибок из функций

Функция, которая может завершиться неудачей, всегда возвращает error последним значением:

func Divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль запрещено")
    }
    return a / b, nil
}

Правило: Если ошибка есть (err != nil), остальные возвращаемые значения часто невалидны или равны нулю./

3. Обработка ошибок: паттерн "Ранний возврат"

Не вкладывай код в else. Проверяй ошибку сразу и возвращай управление:

func ProcessData() error {
    data, err := ReadFile()
    if err != nil {
        return fmt.Errorf("не удалось прочитать файл: %w", err)
    }
    
    result, err := Parse(data)
    if err != nil {
        return fmt.Errorf("ошибка парсинга: %w", err)
    }
    
    return nil
}

4. Оборачивание ошибок (fmt.Errorf и %w)

Чтобы сохранить контекст (где именно произошла ошибка), используй %w. Это создает цепочку ошибок, которую можно потом разобрать.

return fmt.Errorf("ошибка в модуле X: %w", originalErr)

5. Проверка конкретных ошибок

    Сравнение: if err == io.EOF { ... } (работает только если это один и тот же объект ошибки).
    errors.Is(): Проверяет, есть ли в цепочке обернутых ошибок конкретная целевая ошибка.
    errors.As(): Позволяет «достать» ошибку определенного типа из цепочки, чтобы посмотреть её поля (например, код ошибки HTTP).

6. Кастомные ошибки

Если стандартного текста мало, создай свою структуру:

type ValidationError struct {
    Field string
    Value string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("поле %s имеет недопустимое значение: %s", e.Field, e.Value)
}

7. panic и recover

    panic останавливает выполнение программы (используется редко, только при фатальных сбоях).
    recover позволяет перехватить панику внутри горутины, но в обычном синхронном коде лучше полагаться на error.

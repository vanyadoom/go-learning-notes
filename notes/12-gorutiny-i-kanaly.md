# Конспект 12. Горутины и каналы

Это то, за что Go особенно ценят на собеседованиях backend-разработчика — конкурентность встроена в язык, а не является библиотекой поверх него.

## 1. Горутины (goroutines)

Горутина — лёгкий поток выполнения, управляемый рантаймом Go, а не операционной системой напрямую. Стартовый размер стека горутины — всего около 2 КБ (у ОС-потока — обычно мегабайты), поэтому в одной программе можно запускать десятки тысяч горутин без проблем.

```go
func sayHello() {
    fmt.Println("Привет из горутины!")
}

func main() {
    go sayHello() // запуск в отдельной горутине — не блокирует main
    time.Sleep(100 * time.Millisecond) // без этого main может завершиться раньше, чем горутина успеет отработать!
}
```

**Критически важно понимать:** когда завершается функция `main()`, программа завершается целиком, **не дожидаясь** незавершённых горутин. `time.Sleep` в примере выше — это временный, "грубый" способ подождать; в реальном коде для синхронизации используются каналы или `sync.WaitGroup` (см. конспект 13).

```go
go func() {
    fmt.Println("анонимная горутина")
}()
```

## 2. Каналы (channels) — способ горутинам обмениваться данными

Философия Go: *"не общайтесь через разделяемую память — разделяйте память через общение"* (Do not communicate by sharing memory; instead, share memory by communicating).

```go
ch := make(chan int)      // небуферизованный канал
ch2 := make(chan int, 5)  // буферизованный канал ёмкостью 5

ch <- 42        // отправка значения в канал
value := <-ch   // получение значения из канала
```

### Небуферизованный канал — синхронная передача

```go
func worker(ch chan string) {
    ch <- "результат работы"
}

func main() {
    ch := make(chan string)
    go worker(ch)
    result := <-ch // main БЛОКИРУЕТСЯ здесь, пока worker не отправит значение
    fmt.Println(result)
}
```

Отправка в небуферизованный канал блокирует горутину-отправителя, пока кто-то не заберёт значение получением. Это создаёт естественную точку синхронизации между горутинами.

### Буферизованный канал — асинхронная передача до заполнения буфера

```go
ch := make(chan int, 2)
ch <- 1 // не блокирует, есть место в буфере
ch <- 2 // не блокирует
ch <- 3 // ЗАБЛОКИРУЕТСЯ — буфер полон, пока кто-то не прочитает
```

## 3. Закрытие канала и range по каналу

```go
func producer(ch chan int) {
    for i := 1; i <= 5; i++ {
        ch <- i
    }
    close(ch) // сигнализирует, что больше значений не будет
}

func main() {
    ch := make(chan int)
    go producer(ch)

    for value := range ch { // цикл автоматически завершится, когда канал закрыт И пуст
        fmt.Println(value)
    }
}
```

**Правила закрытия каналов (частый вопрос на собеседовании):**
1. Закрывать канал должен **отправитель**, а не получатель.
2. Отправка в закрытый канал — паника: `panic: send on closed channel`.
3. Получение из закрытого (и уже пустого) канала не паникует — возвращает нулевое значение немедленно.
4. Повторное закрытие уже закрытого канала — тоже паника.

```go
value, ok := <-ch // ok == false, если канал закрыт и пуст
if !ok {
    fmt.Println("канал закрыт, данных больше нет")
}
```

## 4. Направленные каналы (channel direction)

Можно ограничить канал в сигнатуре функции только на отправку или только на получение — компилятор проверит корректность использования:

```go
func send(ch chan<- int) { // только отправка
    ch <- 1
}

func receive(ch <-chan int) { // только получение
    fmt.Println(<-ch)
}
```

## 5. Классический паттерн: worker pool

Пул горутин-обработчиков, разбирающих задачи из общего канала — один из самых частых практических паттернов и любимая тема для практического задания на собеседовании:

```go
func worker(id int, jobs <-chan int, results chan<- int) {
    for j := range jobs {
        fmt.Printf("воркер %d обрабатывает задачу %d\n", id, j)
        time.Sleep(time.Millisecond * 100) // имитация работы
        results <- j * 2
    }
}

func main() {
    jobs := make(chan int, 100)
    results := make(chan int, 100)

    // запускаем 3 воркера
    for w := 1; w <= 3; w++ {
        go worker(w, jobs, results)
    }

    // отправляем 9 задач
    for j := 1; j <= 9; j++ {
        jobs <- j
    }
    close(jobs) // воркеры узнают, что новых задач не будет

    for a := 1; a <= 9; a++ {
        <-results // собираем все результаты
    }
}
```

## 6. Пайплайны (pipelines) — цепочки обработки через каналы

```go
func generate(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for _, n := range nums {
            out <- n
        }
    }()
    return out
}

func square(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for n := range in {
            out <- n * n
        }
    }()
    return out
}

func main() {
    for result := range square(generate(1, 2, 3, 4)) {
        fmt.Println(result) // 1 4 9 16
    }
}
```

Каждая стадия пайплайна — отдельная функция, возвращающая канал; данные текут по цепочке горутин, каждая занимается своим шагом обработки.
